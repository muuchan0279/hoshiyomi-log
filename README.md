# HOSHIYOMI LOG // 星読みログ

個人ホロスコープ × 一般の星座占い × 日記を記録して、**日付を伏せたブラインド評価で「本当に当たるのか」を自分で検証する**ローカルアプリ。
社会全体を読むマンデン占星術のタブ(逆行カレンダー・サイン移動・太陽との会合・社会の星読み)もある。

## 起動

```bash
pip install -r requirements.txt
./run.sh          # または python app.py
```

初回は「設定」タブで出生データを入れて保存。

`run.sh` はネイティブ Wayland(`QT_QPA_PLATFORM=wayland`)と `QT_IM_MODULE=wayland` で起動する。
pip 版 PyQt6 はシステムの fcitx プラグインを読めないので、日本語入力は Wayland の text-input プロトコルを使う。

## 仕組み

| ファイル | 役割 |
|---|---|
| `astro_core.py` | 天体計算(Skyfield + 同梱 DE421、1900〜2050年)。トロピカル黄経、ASC/MC、ホールサインハウス、逆行判定、アスペクト。社会用に留・シャドウ・サイン移動・太陽との会合(内合/外合/合/衝)・天体どうしのアスペクト |
| `store.py` | SQLite 保存(`~/.hoshiyomi/hoshiyomi.db`)、ブラインド評価の出題・集計(片側二項検定)、社会の星読みと振り返り |
| `app.py` | PyQt6 GUI |
| `art/gen_icon.py` | アイコン(32×32 のドット絵を 128px に拡大) |

- **外部送信なし**:出生データも日記もローカルの DB にだけ保存。地名検索もしない(緯度経度を直接入力)。
- **星読み文はローカル LLM**:動いている `llama-server` を自動で見つけてつなぐ(`/proc` のコマンドラインからポート・モデル・ctx を読み、`/v1/models` で準備できているか確かめる。複数あれば :8000 優先)。上のバーに今のモデルを表示。設定で手動の OpenAI 互換エンドポイントにも切り替えられる。つながらないときは簡易ルール文で代わりに書く。
- **個人の星読みでは LLM に日付を書かせない**(ブラインド評価で日付がヒントにならないように)。

## 毎日の流れ

1. **星読み**タブ:「星読みを生成」→ 一般の星座占いも貼る → 保存
2. **日記**タブ:夜に、占いを見返さずにその日の出来事を書く
3. **ブラインド評価**タブ:2週間以上たってから解く。日記1件に対し、日付を伏せた占い文4件から一番当てはまるものを選ぶ
   - 偶然の正解率は25%。個人ホロスコープと一般占いを別々に集計して比べる
   - 10問以上・p<0.05 で「偶然より当たってる」表示

## 社会タブ

- **タイムライン(1年)**:水星〜冥王星の逆行(黄)、シャドウ(薄い帯)、サイン移動(星座記号)、太陽との会合(●合 / ○衝)。クリックでその日へ移動
- **一覧**:シャドウ入り/逆行開始/順行に戻る/シャドウ明け/サイン移動/会合を時刻・度数つきで
- **社会の星読み**:今週/今月/今年を選んで、その期間の天体の出来事を LLM に渡して世の中の流れを占う。実在の国・人・ニュースの名前は出させない(LLM の知識が古く作り話になるため)
- **振り返り**:期間が過ぎたら実際どうだったかを書いて、当たり度 1〜5 を付ける。期間ごとの平均を表示
- 社会の配置はゆっくり動き、隣り合う日の文がほぼ同じになるので、ブラインド評価には混ぜていない

計算は日ごとの位置で当たりを付けて1時間刻みで詰めている(精度±30分)。
